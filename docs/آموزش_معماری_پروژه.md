## 🏗️ معماری کلی (MVVM Pattern)

این پروژه از الگوی **MVVM** (Model-View-ViewModel) استفاده می‌کند. این الگو به ما کمک می‌کند کد را مرتب و قابل نگهداری نگه داریم.

### ساختار کلی:

```
┌─────────────────────────────────────────┐
│           VIEW (رابط کاربری)            │
│  (views/pages/, views/widgets/)         │
└──────────────┬──────────────────────────┘
               │
               │ Signals/Slots (ارتباط)
               │
┌──────────────▼──────────────────────────┐
│        VIEWMODEL (لایه نمایش)          │
│      (viewmodels/)                      │
└──────────────┬──────────────────────────┘
               │
               │
┌──────────────▼──────────────────────────┐
│        CONTROLLER (کنترلر)              │
│      (controllers/)                     │
└──────────────┬──────────────────────────┘
               │
               │
┌──────────────▼──────────────────────────┐
│        SERVICE (منطق کسب‌وکار)          │
│      (services/)                        │
└──────────────┬──────────────────────────┘
               │
               │
┌──────────────▼──────────────────────────┐
│        MODEL (مدل داده)                 │
│  (models/, models/db/)                  │
└─────────────────────────────────────────┘
```

### چرا از MVVM استفاده می‌کنیم؟

1. **جداسازی مسئولیت‌ها**: هر لایه فقط یک کار انجام می‌دهد
2. **قابل تست بودن**: می‌توانیم هر بخش را جداگانه تست کنیم
3. **قابل نگهداری**: اگر مشکلی پیش آمد، می‌دانیم کجا باید بگردیم
4. **قابل توسعه**: می‌توانیم ویژگی‌های جدید را راحت اضافه کنیم

## 🚀 شروع برنامه (Entry Point)

### فایل: `main.py`

این فایل نقطه شروع برنامه است. مثل در ورودی یک خانه!

```python
# main.py
import sys
from views.main_frameless_window import MainFramelessWindow
from PyQt6.QtWidgets import QApplication
from configg.config_pages import ConfigPages
from services.db_session import init_db
from utils.stylesheet_loader import load_stylesheet

# 1. ساخت برنامه PyQt
app = QApplication(sys.argv)

# 2. بارگذاری استایل تاریک
dark_stylesheet = load_stylesheet("styles/dark.qss")
app.setStyleSheet(dark_stylesheet)

# 3. ایجاد جداول پایگاه داده (اگر وجود نداشته باشند)
init_db()

# 4. ساخت و پیکربندی صفحات
config = ConfigPages()

# 5. نمایش صفحه Dashboard
config.window.switch_page("Dashboard")
config.window.show()

# 6. اجرای برنامه (حلقه اصلی)
sys.exit(app.exec())
```

### توضیح گام به گام:

1. **QApplication**: این کلاس اصلی PyQt است که برنامه را مدیریت می‌کند
2. **load_stylesheet**: استایل (رنگ‌ها، فونت‌ها) را از فایل QSS بارگذاری می‌کند
3. **init_db()**: جداول پایگاه داده را ایجاد می‌کند
4. **ConfigPages**: تمام صفحات و کنترلرها را آماده می‌کند
5. **app.exec()**: برنامه را اجرا می‌کند و منتظر رویدادها می‌ماند

```python
# models/task_models.py
class TaskModel:
    def __init__(self, title: str, description: str = "", ...):
        self.id: str = uuid.uuid4().hex  # شناسه یکتا
        self.title: str = title
        self.description: str = description
        self.priority: str = priority

        self.completed: bool = completed
        # ...
```

**چرا از Domain Model استفاده می‌کنیم؟**
- مستقل از پایگاه داده است
- می‌توانیم منطق کسب‌وکار را در آن قرار دهیم
- تبدیل به JSON یا فرمت‌های دیگر راحت است

#### 2. **Entity Models** (`models/db/task_entity.py`)

این مدل‌ها مستقیماً با پایگاه داده کار می‌کنند (با استفاده از SQLAlchemy ORM).

```python
# models/db/task_entity.py
class TaskEntity(Base):
    __tablename__ = "tasks"
    
    id: Mapped[str] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(255))
    description: Mapped[str] = mapped_column(String(1000))
    user_id: Mapped[str] = mapped_column(ForeignKey("users.id"))
    user: Mapped["UserEntity"] = relationship(back_populates="tasks")
```

**چرا از Entity استفاده می‌کنیم؟**
- SQLAlchemy به صورت خودکار SQL می‌نویسد
- روابط بین جداول را مدیریت می‌کند
- Migration (تغییرات پایگاه داده) را راحت می‌کند

### Mapper (`mapper/task_mapper.py`)

Mapper ها داده را بین Domain Model و Entity تبدیل می‌کنند.

```python
# mapper/task_mapper.py

# تبدیل Entity به Model (برای استفاده در برنامه)
def map_entity_to_model(entity: TaskEntity) -> TaskModel:
    return TaskModel(
        task_id=entity.id,
        title=entity.title,
        # ...
    )

# تبدیل Model به Entity (برای ذخیره در دیتابیس)
def map_model_to_entity(model: TaskModel) -> TaskEntity:
    return TaskEntity(
        id=model.id,
        title=model.title,
        # ...
    )
```

**چرا Mapper لازم است؟**
- Domain Model و Entity ممکن است ساختار متفاوتی داشته باشند
- می‌توانیم تبدیل‌های پیچیده را در یک جا انجام دهیم
- اگر ساختار یکی تغییر کرد، فقط Mapper را تغییر می‌دهیم

## 🔧 لایه Service (منطق کسب‌وکار)

### فایل: `services/task_service.py`

Service ها منطق کسب‌وکار و دسترسی به داده را مدیریت می‌کنند.

```python
# services/task_service.py
class TaskService:
    def get_tasks_by_user(self, user_id: str) -> List[TaskEntity]:
        with get_session() as db:
            return db.query(TaskEntity).filter(
                TaskEntity.user_id == user_id
            ).all()
    
    def add(self, task: TaskEntity):
        with get_session() as db:
            db.add(task)
            db.commit()
            db.refresh(task)
            return task
```

### توضیح:

1. **get_session()**: یک session پایگاه داده برمی‌گرداند (مثل باز کردن یک فایل)
2. **with**: بعد از استفاده، session به صورت خودکار بسته می‌شود
3. **db.query()**: یک query (درخواست) به پایگاه داده می‌فرستد
4. **db.commit()**: تغییرات را ذخیره می‌کند

### چرا Service لازم است؟

- **جداسازی منطق**: منطق کسب‌وکار از UI جدا می‌شود
- **قابل استفاده مجدد**: می‌توانیم از یک Service در چند جا استفاده کنیم
- **قابل تست**: می‌توانیم Service را بدون UI تست کنیم

### سایر Service ها:

- `user_service.py`: مدیریت کاربران
- `project_service.py`: مدیریت پروژه‌ها
- `idea_service.py`: مدیریت ایده‌ها

## 🎮 لایه Controller (کنترلر)

### فایل: `controllers/task_controller.py`

Controller ها بین View و Service ارتباط برقرار می‌کنند. مثل یک مترجم!

```python
# controllers/task_controller.py
class TaskController(QObject):
    def __init__(self, page_todolist, page_editore, ...):
        self.page_todolist = page_todolist
        self.task_service = TaskService()
        self._connect_signals()  # اتصال سیگنال‌ها
    
    def _connect_signals(self):
        # وقتی کاربر یک کار جدید اضافه می‌کند
        self.page_todolist.handle_quick_add.connect(
            self.handel_quick_tasknew
        )
    
    def handel_quick_tasknew(self, titel: str):
        # 1. ساخت Model جدید
        task = TaskModel(titel)
        
        # 2. ذخیره در Session (حافظه موقت)
        Task_Session.add_task(task)
        
        # 3. ذخیره در پایگاه داده (اگر کاربر لاگین کرده)
        if not Session.is_guest():
            entity = map_model_to_entity_by_userid(
                task, Session.get_id_user()
            )
            self.task_service.add(entity)
```

### Signals و Slots در PyQt:

**Signal**: یک رویداد است (مثل کلیک دکمه)
**Slot**: تابعی که وقتی Signal فراخوانی می‌شود اجرا می‌شود

```python
# در View (TodoListPage):
handle_quick_add = pyqtSignal(str)  # تعریف Signal
self.handle_quick_add.emit("کار جدید")  # فراخوانی Signal

# در Controller:
self.page_todolist.handle_quick_add.connect(
    self.handel_quick_tasknew  # Slot
)
```

### چرا Controller لازم است؟

- **جداسازی**: View فقط UI است، Controller منطق را مدیریت می‌کند
- **قابل تست**: می‌توانیم Controller را بدون UI تست کنیم
- **قابل استفاده مجدد**: می‌توانیم یک Controller را با چند View استفاده کنیم

```python
class TodoListPage(QWidget):

    handle_quick_add = pyqtSignal(str)
    handle_edite_window = pyqtSignal(TaskModel)
    
    def __init__(self):
        super().__init__()
        self.init_ui()
    
    def init_ui(self):
        layout = QVBoxLayout(self)
        
        # فیلد ورودی
        self.task_input = QLineEdit()
        self.task_input.returnPressed.connect(self.quick_add)
        
        # لیست کارها
        self.task_list = QListWidget()
        
        layout.addWidget(self.task_input)
        layout.addWidget(self.task_list)

        title = self.task_input.text()
        if title:
            # فراخوانی Signal
            self.handle_quick_add.emit(title)
            self.task_input.clear()
```

## 👤 مدیریت Session (جلسه کاربر)

### فایل: `core/session_manager.py`

Session اطلاعات کاربر فعلی را نگه می‌دارد.

```python
# core/session_manager.py
class SessionManager(QObject):
    def __init__(self):
        self._current_user: Optional[UserModel] = None
        self._is_guest: bool = False
    
    def set_user(self, user: UserModel):
        self._current_user = user
        self._is_guest = False
    
    def set_guest(self):
        self._is_guest = True
        self._current_user = None
    
    def is_guest(self) -> bool:
        return self._is_guest

# Singleton: فقط یک نمونه از Session وجود دارد
Session = SessionManager()
```

**Singleton Pattern**: فقط یک نمونه از Session در کل برنامه وجود دارد. همه جا می‌توانیم از `Session` استفاده کنیم.

### فایل: `core/session_task.py`

این فایل کارهای فعلی کاربر را در حافظه نگه می‌دارد (بدون نیاز به خواندن از دیتابیس).

```python
# core/session_task.py
class TaskSession(QObject):
    task_session_new = pyqtSignal(TaskModel)
    task_session_edit = pyqtSignal(TaskModel)
    
    def __init__(self):
        self._tasks: List[TaskModel] = []
    
    def add_task(self, task: TaskModel):
        self._tasks.append(task)
        self.task_session_new.emit(task)
    
    def get_all(self) -> List[TaskModel]:
        return self._tasks

Task_Session = TaskSession()
```

**چرا Session لازم است؟**
- **سرعت**: نیازی نیست هر بار از دیتابیس بخوانیم
- **سازگاری**: همه جا از یک منبع داده استفاده می‌کنیم
- **بهینه‌سازی**: فقط وقتی لازم است به دیتابیس می‌نویسیم

## 💾 پایگاه داده و Migration

### فایل: `services/db_session.py`

این فایل اتصال به پایگاه داده را مدیریت می‌کند.

```python
# services/db_session.py
DATABASE_URL = "sqlite:///data/tasks.db"

# ساخت Engine (موتور پایگاه داده)
engine = create_engine(DATABASE_URL, echo=True)

# ساخت Session Factory
SessionLocal = sessionmaker(bind=engine)

# Context Manager برای مدیریت Session
@contextmanager
def get_session() -> Generator[Session, None, None]:
    session = SessionLocal()
    try:
        yield session
    finally:
        session.close()  # همیشه بسته می‌شود
```

**SQLite**: یک پایگاه داده سبک که در یک فایل ذخیره می‌شود (`data/tasks.db`)

### Migration با Alembic

**Migration**: تغییرات ساختار پایگاه داده (مثل اضافه کردن ستون جدید)

```bash
# ساخت Migration جدید
alembic revision --autogenerate -m "اضافه کردن ستون جدید"

# اعمال Migration
alembic upgrade head
```

فایل‌های Migration در `alembic/versions/` هستند.

## 🔄 جریان داده در برنامه

بیایید ببینیم وقتی کاربر یک کار جدید اضافه می‌کند چه اتفاقی می‌افتد:

```
1. کاربر در TodoListPage تایپ می‌کند و Enter می‌زند
   ↓
2. TodoListPage.quick_add() فراخوانی می‌شود
   ↓
3. Signal handle_quick_add.emit(title) فراخوانی می‌شود
   ↓
4. TaskController.handel_quick_tasknew(title) اجرا می‌شود
   ↓
5. TaskModel جدید ساخته می‌شود
   ↓
6. Task_Session.add_task(task) - اضافه به حافظه
   ↓
7. اگر کاربر لاگین کرده:
   - map_model_to_entity_by_userid() - تبدیل Model به Entity
   - TaskService.add(entity) - ذخیره در دیتابیس
   ↓
8. Signal task_session_new.emit(task) فراخوانی می‌شود
   ↓
9. TodoListPage.create_task_item_widget(task) - نمایش در UI
```

```python
def handel_quick_tasknew(self, titel: str):

    if not Session.is_guest():
        # ...
```

**بعد:**
```python
# در ViewModel
def add_quick_task(self, title: str):
    task = TaskModel(title)
    Task_Session.add_task(task)
    if not Session.is_guest():
        # ...

# در Controller
def handel_quick_tasknew(self, title: str):
    self.viewmodel.add_quick_task(title)
```

### 2. **مدیریت خطا (Error Handling)**

اضافه کردن try-except برای مدیریت خطاها:

```python
def add(self, task: TaskEntity):
    try:
        with get_session() as db:
            db.add(task)
            db.commit()
            db.refresh(task)
            return task
    except Exception as e:
        logger.error(f"Error adding task: {e}")
        raise
```

## 🎓 خلاصه و نکات مهم

### نکات کلیدی:

1. **MVVM Pattern**: جداسازی لایه‌ها باعث می‌شود کد تمیز و قابل نگهداری باشد
2. **Signals/Slots**: روش PyQt برای ارتباط بین کامپوننت‌ها
3. **Session**: نگه‌داری داده در حافظه برای بهبود عملکرد
4. **Mapper**: تبدیل بین Domain Model و Entity
5. **Service**: منطق کسب‌وکار جدا از UI

### جریان کار:

```
View → Controller → Service → Database
  ↑                              ↓
  └────────── Session ←──────────┘
```

### فایل‌های مهم برای شروع توسعه:

1. `main.py` - نقطه شروع
2. `configg/config_pages.py` - پیکربندی صفحات
3. `controllers/task_controller.py` - منطق کنترل
4. `services/task_service.py` - منطق کسب‌وکار
5. `views/pages/todolist_page.py` - رابط کاربری
